1Problem statement

Retention offers are created, approved and tracked across disconnected spreadsheets and email threads. There is no enforced approval workflow, no shared record of an offer's state, and no reliable measurement of which offers retain customers. Discount margin leaks, duplicate offers reach the same customer, approved offers are never sent, and management has no trustworthy view of retention performance. CROP provides a role-based web application in which every offer moves through an enforced status workflow, is searchable by the whole team, and is aggregated into a live dashboard — built, tested, containerised and deployed by an automated DevOps pipeline.

4Constraints

  • C1 Single developer, ~2 weeks → scope frozen at 15 items, no microservices
  • C2 Must run entirely on one macOS laptop → no cloud spend
  • C3 Prescribed toolchain must be demonstrable → Maven + WAR + Tomcat
  • C4 No DB licence → embedded H2 file database
  • C5 No real customer data → synthetic seed data only
  • C6 No email gateway → "send" transitions status, does not email
  • C7 Live 20-minute viva → every tool needs a visible interface
